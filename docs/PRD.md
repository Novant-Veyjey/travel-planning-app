## 1. 产品概述

### 1.1 产品定位
一款面向自由行用户的 **智能旅游计划生成 + 卡通地图导航** 应用。用户只需输入 **出发地、目的地、游玩天数**，系统即可结合 **两地天气、地形地貌、用户精力状态**，自动生成 **多条游玩路线**，并提供 **交通工具、打卡店铺、打卡地点、推荐打卡时间、网红纪念馆等网红景点** 的完整规划。

### 1.2 核心价值
- **省心**：一键生成多套完整的游玩路线，无需自己做攻略。
- **沉浸**：卡通地图 + 天气地形实时联动，天气直接呈现在页面中（如下雨页面就下雨、人物打伞），无需传统天气报告。
- **个性化**：用户可自定义卡通形象（发型/服装），并根据用户精力调整路线强度。

### 1.3 目标用户
- 自由行爱好者（18-45 岁）
- 想"无脑跟玩"但又不喜欢跟团的年轻人
- 需要亲子/老人等精力受限人群友好路线的家庭用户

## 2. 用户需求分析（四层需求）

| 层级 | 需求内容 |
|------|----------|
| 表层 | 生成一份能直接照做的旅游路线计划 |
| 中间 | 路线要考虑天气、地形、体力，避免踩坑 |
| 深层 | 像有个懂行的朋友陪我玩，帮我安排好一切 |
| 情感 | 有趣、可爱、有"专属感"的旅行体验 |

### 2.1 用户故事（User Story）
1. 作为用户，我希望输入出发地和目的地就能生成路线，这样我省去查攻略时间。
2. 作为用户，我希望天气直接以实时场景呈现在地图上（如页面下雨、人物打伞），而不是看天气报告，这样更有沉浸感。
3. 作为用户，我希望先生成 3 条不同强度的路线（休闲/经典/特种兵）供我选择，选好后只专注显示这一条，这样不被信息干扰。
4. 作为用户，我希望知道每个打卡点推荐的游玩时间，这样我能合理安排行程。
5. 作为用户，我希望地图上能看到自定义形象（发型/服装）的自己，这样有专属感。
6. 作为用户，我希望打卡点数据来自真实 POI，这样信息准确可用。

## 4. 产品流程

### 4.1 核心流程（路线生成 + 选择）
```
用户输入 [出发地 / 目的地 / 游玩天数] 
   ↓
用户自定义形象（发型 / 服装）
   ↓
系统获取 [两地天气 / 目的地地形 / 用户精力]
   ↓
AI 生成 3 条不同强度路线（休闲 / 经典 / 特种兵）
   ↓
3 条路线对比展示，供用户选择 1 条
   ↓
进入卡通地图模式（页面只显示已选路线）
   ↓
地图随天气实时呈现场景、显示地形、标记打卡点
   ↓
用户跟着路线游玩，系统实时提示注意事项
```

### 4.2 天气实时场景化流程
```
目的地天气数据变化（如从晴变雨）
   ↓
卡通地图实时切换场景（晴天阳光 → 雨天落雨滴 + 阴沉天色）
   ↓
卡通人物自动佩戴天气配饰（雨天打伞 / 雪天戴帽围巾）
   ↓
弹出当天游玩注意事项提醒（如"路面湿滑，穿防滑鞋"）
```

> 注：页面**不显示传统天气报告/文字数值**，全部通过实时场景呈现天气。

## 5. 页面规划

### 5.1 页面清单
| 页面 | 说明 |
|------|------|
| 首页/输入页 | 输入出发地、目的地、游玩天数 |
| 形象自定义页 | 选择卡通形象的发型、服装 |
| 路线选择页 | 展示 3 条生成路线（休闲/经典/特种兵）供对比选择 |
| 路线详情页 | 选定路线的每日行程、打卡点、交通方式、时间表 |
| **卡通地图页** | 核心页面：卡通地图 + 实时天气场景 + 地形 + 自定义卡通人物 + 打卡点 |
| 打卡详情页 | 单个打卡点介绍、推荐时间、注意事项 |

### 5.2 核心页面：卡通地图页（重点设计）
| 元素 | 说明 |
|------|------|
| 地图风格 | 卡通扁平化，山丘/河流/树林等地形元素 |
| 自定义卡通人物 | 显示用户自定义形象（发型/服装），实时显示当前位置 |
| **实时跟随导航** | 卡通人物**跟随用户实时位置移动**（类似高德导航）：地图随人物移动实时刷新，人物始终位于画面中心附近 |
| 实时天气场景 | **不显示天气报告/数值**，天气直接体现在页面上：晴天地图上就有一个大大的卡通太阳；雨天页面就下雨、阴沉天色；雪天就飘雪。随天气实时切换 |
| 天气配饰 | 雨天卡通人物自动打伞（画面下雨+撑伞）、雪天戴帽子围巾、晴天直接一个大太阳 |
| 地形随移动变化 | 地图地形随人物当前位置**实时切换**：人物移动时，画面地形（山区/平原/河边/海边）随之变化，而非固定一张地图 |
| 当地建筑 | 地图展示当地特色建筑（民居/鼓楼/纪念馆/塔/桥等），标注建筑类型，随人物位置实时更新周围建筑 |
| 民族特色 | 地图融入当地民族元素（民族建筑花纹、经幡/图腾、石板街等），人物可穿民族服饰 |
| 打卡点 | 第三方 POI 图标标注（标注在对应建筑上），点击查看详情 |
| 路线引导 | 显示前往下一打卡点的路径箭头/虚线，随人物位置实时更新（高德导航式） |
| 路线交通标注 | 推荐的交通方式图标直接**画在路线路径上**，并标注每段耗时（如"地铁15min""步行10min"），直观呈现 |
| 注意事项弹窗 | 进入特定地形/天气时弹出提醒（如"雨天路滑"） |
| 单路线显示 | 只展示用户已选择的 1 条路线及打卡点 |
| 人物比例 | 卡通人物尺寸小巧，与地图比例协调，不遮挡地图与打卡点 |
| 人物角度 | 卡通人物采用 **45 度侧身站姿**（微微侧脸），增强真实感与沉浸感 |
| 装扮按钮 | 地图右下角一个**小巧圆形按钮**：极淡柔和水蓝渐变、白色衣架图标、柔和白色光晕投影，点击进入当地装扮页 |
| 顶部天气 | 地图右上角一个**大而醒目的卡通太阳图标**（带笑脸光芒），旁边标注温度小字（如"晴 26°"）；雨天直接下雨+人物打伞 |
| 底部行程面板 | 白色圆角悬浮卡片，采用**竖向时间线**：一行一个打卡点（时间段+彩色图标+地点名），时间连续不重复；卡片含"继续导航""我的路线"按钮 |

### 5.3 形象自定义页
| 元素 | 说明 |
|------|------|
| 页面布局 | 中央实时预览卡通形象，随选项即时变化 |
| 发型选择 | 提供多款发型（长发/短发/双马尾/卷发/寸头等） |
| 服装选择 | 提供多款基础服装（连衣裙/T恤/卫衣/夹克等） |
| **当地服饰选择** | 提供目的地当地的**民族服饰库**，用户可挑选穿戴（如藏族藏袍/苗族银饰/傣族筒裙等） |
| 性别切换 | 男/女形象基础底模 |
| 随机生成 | 一键随机搭配 |
| 确认按钮 | 保存形象并进入下一步（路线生成） |
| 进入方式 | 首次进入时引导自定义；游玩中可从地图页"换装"图标按钮再次进入改服装/当地服饰 |

> **当地装扮功能**：根据用户选择的旅游目的地，在形象自定义页/换装页**动态上线当地特色服饰**供用户选择。到不同地方，可选的当地服饰库随之变化。

### 5.5 交通方式推荐（嵌入路线详情页）
| 元素 | 说明 |
|------|------|
| 展示位置 | 路线详情页每个打卡点之间，或行程节点上 |
| 推荐方式 | 步行/公交/地铁/打车/骑行，标注图标与颜色 |
| 推荐理由 | 说明为何推荐该方式（如"雨天地铁避雨""距离近步行""特种兵推荐骑行省时"） |
| 耗时预估 | 每段交通的预计耗时 |
| 天气/地形联动 | 雨天不推骑行、高海拔少步行等 |
| 替代方式 | 提供 1-2 个备选交通方式 |
| **路线路径绘制** | 推荐的交通方式图标 + 耗时**直接绘制在地图路线路径上**（随路径分段标注），而非只在卡片显示 |

## 6. 数据结构（简要）
| 路线卡片 | 每个卡片含：路线名、适合人群、强度标签（体力消耗值）、特色亮点、每日打卡点数量 |
| 强度标识 | 用图标/颜色区分强度（绿=休闲、蓝=经典、红=特种兵） |
| 对比维度 | 卡片上标注每日步行量、景点数量、用餐安排等 |
| 选中交互 | 点击卡片进入该路线详情，选中后地图页只渲染该条路线 |
| 重新生成 | 不满意可"重新生成 3 条" |

## 7. 技术要点（供研发参考）
- 天气数据：对接第三方天气 API（如和风天气），轮询/推送实时获取目的地天气，驱动地图场景切换。
- 天气场景化：前端根据天气状态叠加粒子/动画（雨滴、雪花、阳光），并切换天色与人物配饰。
- 地形数据：使用地理信息 / 高程数据判断地形。
- POI 数据：对接第三方 POI 服务（如高德/百度地图 POI、大众点评），获取真实打卡店铺、景点、网红纪念馆。
- 卡通地图渲染：Web 端 Canvas / 小程序 Canvas / 游戏引擎（如 Cocos）。
- 自定义形象：提供发型/服装选项，基于性别组合生成卡通形象 + 天气配饰。
- AI 路线生成：调用大模型（如 DeepSeek）根据输入、天气、地形、POI 生成 3 条路线。
- 单路线状态：路线选择后，本地/服务端保存"选定路线"，地图页只渲染该路线。

## 9. 已确认决策 & 开放问题

### 9.1 已确认决策
| 决策点 | 结论 |
|------|------|
| 形象 | 用户可自定义发型/服装 |
| 天气 | 不显示天气报告，实时场景化呈现（雨=落雨+打伞，雪=飘雪等） |
| 路线 | 生成 3 条（休闲/经典/特种兵），用户选 1 条后只显示该条 |
| POI | 对接第三方 POI 数据 |

### 9.2 开放问题
1. 卡通地图用 Web 还是小程序实现？
2. 是否需要支持多目的地（环线游）？
3. 天气实时场景化是否需要后台轮询，还是前端根据天气状态模拟？
4. POI 具体选哪家服务商（高德/百度/点评）？
