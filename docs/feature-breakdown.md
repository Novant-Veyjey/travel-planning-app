## M1 卡通地图与天气场景

### 职责
渲染卡通风格地图，将实时天气**场景化**呈现（不显示天气数值报告），卡通人物**实时跟随导航**（类似高德），地形、特征建筑、天气随人物移动实时更新。

### 子功能拆解
| 子功能 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 卡通地图渲染 | 地图图层数据 | 卡通地形画面 | 山丘/河流/树林/山脉等卡通元素 |
| **实时定位** | GPS/定位信号 | 用户实时坐标 | 持续获取用户位置 |
| **跟随导航** | 用户实时坐标 | 地图视角/人物位置更新 | 人物随用户移动，地图实时刷新，人物居中（高德式跟随） |
| 地形随移动变化 | 人物当前位置 | 当前区域地形 | 人物移动时地形实时切换（山区/平原/河边/海边），非固定地图 |
| 特征建筑实时更新 | 位置 + 建筑数据 | 周围建筑刷新 | 随人物移动，实时更新周围的当地建筑并标注类型 |
| 民族特色渲染 | 区域民族文化 | 民族元素 | 民族建筑花纹、经幡/图腾、石板街，人物可穿民族服饰 |
| 天气场景切换 | 天气状态(晴/雨/雪) | 页面天气效果 | 晴=大太阳、雨=落雨+阴沉、雪=飘雪，随实时天气切换 |
| 天气配饰 | 天气状态 + 人物 | 人物配饰 | 雨=打伞、雪=戴帽围巾、晴=墨镜 |
| 路线引导 | 人物坐标 + 下一打卡点 | 路径箭头/虚线 | 显示前往下一打卡点的路径，随位置实时更新（高德式引导） |
| 路线交通标注 | 推荐交通方式 + 耗时 | 路径上的交通图标/耗时 | 交通方式图标直接画在路线上，并标注每段耗时（如"地铁15min"） |
| 单路线打卡点标注 | 选定路线POI | 地图打卡图标 | 只渲染所选路线，标注在对应建筑上 |

### 技术实现
- 前端 Canvas / DOM 动画渲染
- 实时定位：对接定位 API（高德/百度/微信定位），轮询/监听位置变化
- 天气数据驱动场景状态机（sunny/rainy/snowy）
- 动画：雨滴/雪花粒子系统
- 地形/建筑：按地理区域分块加载，随人物坐标切换渲染
- 民族特色/建筑：区域元数据驱动（建筑类型、民族元素标签）
- 跟随模式：地图平移/缩放随人物位置动态调整，人物居中

### 验收标准
- [ ] 卡通人物跟随用户实时位置移动，地图实时刷新
- [ ] 切换天气状态时，页面场景实时变化
- [ ] 雨天人物自动打伞
- [ ] 地图只显示用户选定的单条路线打卡点
- [ ] 人物移动时，地图地形随位置实时变化
- [ ] 人物移动时，周围特征建筑实时更新
- [ ] 显示前往下一打卡点的路径引导，随位置实时更新
- [ ] 地图融入当地民族元素，人物可穿民族服饰
- [ ] 人物采用 45 度侧身站姿
- [ ] 装扮按钮：右下角小圆形水蓝渐变+衣架图标
- [ ] 顶部大太阳+温度标注；雨天直接下雨+打伞
- [ ] 底部竖向时间线行程面板，时间连续不重复

## M2 路线生成

### 职责
根据用户输入（出发地/目的地/天数/精力）+ 天气地形 + POI，AI 生成 3 条路线（休闲/经典/特种兵）。

### 子功能拆解
| 子功能 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 参数收集 | 出发地/目的地/天数 | 结构化输入 | 接收 M4 数据 |
| 天气地形获取 | 目的地 | 天气+地形数据 | 对接天气API+高程 |
| POI 拉取 | 目的地+偏好 | 打卡点列表 | 对接 M5 |
| AI 路线编排 | 输入+天气+POI | 3条路线JSON | 调用大模型 |
| 路线强度分级 | 路线 | 休闲/经典/特种兵 | 按精力适配打卡点数量/步行量 |

### 技术实现
- 后端路由 `/api/plan/generate`
- 调用 DeepSeek 大模型（提示词注入天气/地形/POI 上下文）
- 返回 3 条路线 JSON

### 验收标准
- [ ] 输入参数后返回 3 条不同强度的路线
- [ ] 路线内容包含每日行程、打卡点、推荐时间、交通
- [ ] 路线强度随用户精力状态调整

## M3 自定义形象

### 职责
用户自定义卡通形象（发型/服装），生成个性化人物，并支持游玩中换装。

### 子功能拆解
| 子功能 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 性别选择 | 男/女 | 基础形象底模 | — |
| 发型选择 | 发型选项 | 形象更新 | 长发/短发/双马尾等 |
| 服装选择 | 服装选项 | 形象更新 | 连衣裙/T恤/卫衣等 |
| 形象预览 | 当前形象 | 实时渲染 | 随选项即时变化 |
| 随机生成 | — | 随机搭配 | 一键随机 |
| 换装入口 | 点击 | 进入自定义页 | 地图角落"换装"按钮 |

### 技术实现
- 前端组件化形象渲染（SVG/Canvas 拼合发型+服装+性别）
- 形象数据本地/后端存储
- 与 M1 天气配饰层叠加

### 验收标准
- [ ] 可选择性别/发型/服装并实时预览
- [ ] 地图页人物使用用户自定义形象
- [ ] 游玩中可通过"换装"按钮改服装
- [ ] 雨天人物形象叠加打伞配饰

## M9 交通工具推荐

### 职责
为每段行程推荐最优交通方式，结合距离、天气、地形、用户精力智能推荐，并给出替代方案。

### 子功能拆解
| 子功能 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 距离测算 | 两个打卡点坐标 | 距离/预计耗时 | 计算点间距离 |
| 交通方式候选 | 距离+地图数据 | 可选方式列表 | 步行/公交/地铁/打车/骑行 |
| 天气地形适配 | 天气+地形+方式 | 过滤后候选 | 雨天不推骑行、高海拔少步行 |
| 精力适配 | 用户精力+方式 | 排序后候选 | 特种兵优先省时方式 |
| 推荐排序 | 各候选评分 | 最优方式+理由 | 结合耗时/体力/天气打分 |
| 替代方案 | 最优方式 | 1-2个备选 | 天气变化时可切换 |
| **路线路径标注** | 最优方式 + 各段耗时 | 路径上的交通图标+耗时 | 把交通方式图标和耗时**绘制在导航路线路径上** |

### 技术实现
- 对接地图 API（高德/百度）获取两点间多方式路线与耗时
- 天气/地形/精力作为权重，参与交通方式评分排序
- 结果嵌入路线详情页行程节点
- 交通方式图标/耗时随导航路径分段渲染（绘制在路径上）

### 验收标准
- [ ] 每段行程给出推荐交通方式 + 耗时 + 推荐理由
- [ ] 雨天不推荐骑行，改为地铁/打车
- [ ] 特种兵路线优先省时方式
- [ ] 提供至少 1 个替代交通方式

## M10 当地装扮

### 职责
根据用户旅游目的地，动态上线当地民族服饰库，供用户为卡通人物选择穿戴（当地装扮功能）。

### 子功能拆解
| 子功能 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 当地服饰库管理 | 目的地 | 当地民族服饰列表 | 按目的地动态上线（如藏族藏袍/苗族银饰/傣族筒裙） |
| 服饰分类 | 服饰数据 | 男款/女款/配饰 | 按性别、类型分类 |
| 服饰试穿预览 | 服饰+形象 | 形象实时更新 | 选中即在预览中穿戴 |
| 穿戴保存 | 选定服饰 | 形象持久化 | 存入用户形象 |
| 地图穿戴展示 | 形象数据 | 人物穿戴民族服饰 | 地图页人物展示当地服饰 |
| 服饰库随目的地变化 | 切换目的地 | 更新服饰库 | 到不同地方可选服饰随之变化 |

### 技术实现
- 前端组件化服饰渲染（SVG/Canvas 拼接民族服饰图层）
- 服饰数据按目的地/民族维度管理，接口返回对应服饰库
- 与 M3 自定义形象、M1 天气配饰层叠加渲染

### 验收标准
- [ ] 根据目的地动态展示当地民族服饰库
- [ ] 用户可选择穿戴并实时预览
- [ ] 地图页人物展示所选的当地服饰
- [ ] 切换目的地后，可选当地服饰库随之变化

## 开发优先级建议（拆分任务）
1. **第一阶段**（快速原型）：M4 → M5 → M2（能生成路线）
2. **第二阶段**：M9（交通工具推荐）→ M3（自定义形象）
3. **第三阶段**：M10（当地装扮）→ M1（卡通地图+天气场景）
4. **第四阶段**：M6 → M7 → M8（完善体验）

> 每个核心模块 M1/M2/M3/M9/M10 均可独立验收，满足作业"至少3个核心功能模块"要求。
